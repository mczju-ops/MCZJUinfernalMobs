# InfernalMobs 配置迁移指南

> 本文随重构持续更新，用于最终停服迁移正式服配置。不要直接用新版覆盖正式服目录。

## 迁移原则

- 迁移前完整备份 `plugins/InfernalMobs/`。
- 在服务器停止状态下手工迁移；新版不会读取旧键，也不会自动转换旧文件。
- 先在测试服完成所有配置加载和玩法验证，再迁移正式服。
- `config-version` 当前固定为 `1`。缺失或不支持的版本会拒绝本次加载。
- 已存在的插件目录缺少必需配置文件时，插件不会自动覆盖管理员现场。

## 第一阶段：核心配置

新版核心文件：

```text
plugins/InfernalMobs/
├─ config.yml
├─ skills.yml
├─ regions.yml
└─ messages.yml
```

测试服已有旧插件目录时，请先停服备份，然后用本仓库 `src/main/resources/` 中的上述四个文件替换测试服对应文件。加载器不会在已有目录中自动补齐缺失文件。暂时保留旧掉落文件和运行数据文件。

本阶段的回滚边界也是这四个文件和对应插件 jar：若测试未通过，停服后恢复备份的旧 jar 与旧配置，不要把新版四文件留给旧 jar 混用。本阶段未改写掉落或运行数据格式。

### config.yml

| 旧位置 | 新位置 | 处理 |
| --- | --- | --- |
| 无 | `config-version` | 新增，填写 `1` |
| `debug` | `debug` | 原值迁移 |
| `exp-multiplier` | `exp-multiplier` | 原值迁移 |
| `enabled-worlds` | `enabled-worlds` | 原值迁移 |
| `infernal-spawn-reasons` | `infernal-spawn-reasons` | 原值迁移 |
| `defaults.infernal.allow-types` | `allow-types` | 暂按原值迁移，正式服迁移时确认是否仍有用途 |
| `defaults.infernal.deny-types` | 删除 | 新版不支持全局黑名单 |
| `mob-registry` | 删除 | 不再进行插件自定义不活跃清理或关服杀怪 |

### skills.yml

| 旧位置/文件 | 新位置 | 处理 |
| --- | --- | --- |
| `config.yml:skill-weights` | `pools.default` | 改为命名词条池 |
| 区域内联 `skill-pool` | `pools.<名称>` | 提取为命名池，区域只引用池名 |
| `config.yml:skills.<id>` | `skills.<id>` | 迁移技能参数 |
| `skill_name.yml:<id>` | `skills.<id>.display` | 合并显示名后删除旧文件 |
| `skills.<id>.type` | 删除 | 技能类型由源码定义 |
| `skills.morph.morph-types` | `regions.yml:base-rules.morph-pool` | 变形池属于生成规则 |

`pools` 中只填写已注册词条 ID，权重必须大于 0。区域引用不存在的池时，该区域会被跳过。

### regions.yml

- `base-rules` 是未命中区域时使用的完整规则。
- `regions.<id>.overrides` 只允许：
  - `levels.weights`
  - `skill-pool`
  - `affix-count`
  - `morph-pool`
- 覆写字段存在时整体替换，缺失时继承 `base-rules`。
- `min`、`max` 改为固定三整数列表 `[x, y, z]`。
- 等级只保留逐等级权重，不迁移 `level-min`、`level-max`、`level-ranges`、`levelChance` 等旧写法。
- `affix-count.formula` 只允许 `level`；删除 `tier-threshold`。
- 区域内联实体白名单、黑名单全部删除。
- `presets` 整体删除。

旧字段示例：

```yaml
levelChance:
  "1": 25
skill-pool:
  poisonous: 10
```

迁移后示例：

```yaml
overrides:
  levels:
    weights:
      "1": 25
  skill-pool: spawn
```

### messages.yml

| 旧位置 | 新位置 |
| --- | --- |
| `config.yml:death-messages` | `messages.yml:death-messages` |
| `config.yml:protected-animals` | `messages.yml:protected-animals` |

布尔开关键统一使用 `enabled`。`mob_name.yml` 不迁移，原版实体名已经改用客户端翻译组件。

## 第二阶段：实体 PDC 与生命周期

新版炒鸡怪使用 `mczju:infernal_mob` 的 `TAG_CONTAINER` 保存实体状态，当前 `data-version` 为 `1`。容器内保存：

- `data-version`
- `level`
- `affixes`
- `suppressed-affixes`
- `used-one-time`
- `morph-targets`

ID 列表统一为小写逗号分隔字符串。冷却、临时 Buff、技能会话、延迟任务和 `StatMap` 不迁移到 PDC；实体重新加载后这些运行期状态重置。

旧 `im_level` 不再是炒鸡怪身份标记，也不会触发恢复或删除。正式服停服迁移时不需要转换存量实体标签；建议在更换 jar 前按服务器运维习惯清理旧版存量炒鸡怪，或让其之后按原版规则自然消失。新版不会提供 `/im cleantags`。

实体恢复只重建内存状态，不重复执行 `onEquip`、属性倍率、装备或坐骑生成。PDC 缺字段、类型错误、版本不支持时只记录中文警告并保留实体。

## 第三阶段：运行数据

停服迁移时手工移动以下文件；新版不会探测根目录旧文件：

| 旧位置 | 新位置 |
| --- | --- |
| `plugins/InfernalMobs/kill_stats.yml` | `plugins/InfernalMobs/data/kill_stats.yml` |
| `plugins/InfernalMobs/guaranteed_loot_progress.yml` | `plugins/InfernalMobs/data/guaranteed_loot_progress.yml` |

文件内容格式本阶段不变，只调整目录和保存生命周期。运行期间查询、击杀累计及保底累计只访问内存；每分钟创建稳定快照并异步保存，插件关闭时执行最终保存。保存任务不会重叠，写盘失败后保持脏状态并在下一周期重试。

`GuaranteedLootService` 现在在插件启用期间保持同一实例。后续掉落配置 reload 只能替换其不可变配置引用，不得重新读取或清空上述进度文件。

## 第五阶段：技能注销生命周期

本阶段只统一技能会话的注销边界：

- 实体死亡：按词条装配的逆序调用 `onUnequip`，然后注销 `MobState`。
- `/im clear` 主动清除：先调用 `onUnequip`，再移除实体和注销状态。
- 变形：旧实体先调用 `onUnequip`，再移除旧实体；新实体只执行后续必要的装配流程。
- 区块卸载：只同步 PDC 并注销内存状态，不调用 `onUnequip`，避免移除仍需保留的常驻装配效果。
- 插件关闭：只保存实体状态并释放内存引用，不主动移除实体效果。
- `morph` 的下一 tick 延迟任务按实体 UUID 记录；实体死亡、主动清除或变形卸载时会取消尚未执行的旧任务。
- `sulfur` 的喷泉周期任务按实体 UUID 记录用于防重复；初始触发成功后属于脱手技能，实体卸载不会取消，任务使用释放时快照完成喷发。

单个词条的 `onUnequip` 抛出异常时只记录警告，其他词条仍会继续卸载。冷却、临时 Buff 和变形状态继承语义不在本阶段改变。

## 第四阶段：掉落与保底配置

停服迁移时按下表重组文件。新版不会读取旧位置，也不会自动生成迁移后的文件：

| 旧位置 | 新位置 | 处理方式 |
| --- | --- | --- |
| `loot.yml` | `loot/settings.yml` | `enable` 改为 `enabled`；`rotation.enable` 改为 `rotation.enabled`；删除 `drop-times.enable` |
| `special_loot.yml` | `loot/settings.yml:special` | 合并为 `special.enabled`、`item-id`、`rates` |
| `loot/<等级>.yml` | `loot/levels/<等级>.yml` | `rewards` 内容保持；奖励 ID 只接受 `id` |
| `guaranteed_loot.yml` | `loot/guaranteed.yml` | 按下述新规则手工重写 |
| `loot_name.yml` | 不迁移 | 删除；玩家可见名称读取实际 `ItemStack` 组件 |
| `loot/eg.yml` | 不迁移 | 删除示例文件 |

保底字段映射：

- `enable` 改为 `enabled`，`rotation.enable` 改为 `rotation.enabled`。
- `rotation.sets` 必须不小于实际使用的最大 `rotation-set`；新版随包默认等级池使用 1 至 6。
- `count` 改为 `required-rolls`，单位明确为等级池实际抽取次数。
- `reset-on-drop` 改为 `reset-after-reward`。
- 单个规则的 `item-id`、`item-amount` 改为 `rewards` 列表中的 `item-id`、`amount`。
- 删除 `progress-id`、`pity-group` 和 `group-id`。规则 ID 就是进度 ID。
- 原来多条规则共享 `progress-id` 的轮换奖励，应合并为一条规则，并把各奖励及其 `rotation-set` 放入同一个 `rewards` 列表。

为保留已有进度，新规则 ID 应使用旧数据文件中的进度键：旧规则没有 `progress-id` 时沿用旧规则 ID；旧规则共享 `progress-id` 时，新合并规则使用该 `progress-id` 作为规则 ID。必要时停服手工重命名 `data/guaranteed_loot_progress.yml` 中对应键。

`/im reload` 现在会先完整解析核心与掉落配置。任一必需文件缺失或根本性损坏时不提交本次重载；无效的单个等级池奖励或保底规则会被跳过并输出路径诊断。保底服务实例和内存进度不会在 reload 时替换或重读。

## 测试服检查记录

- [ ] 四个核心文件均可加载，启动日志无配置错误。
- [ ] 修改任一核心文件后 `/im reload` 成功并显示诊断数量。
- [ ] 制造 YAML 语法错误后 reload 失败，旧快照继续生效。
- [ ] 未命中区域时按 `base-rules.levels.weights` 抽取。
- [ ] `spawn_zone`、`abyssal01`、`abyssal02` 命中及优先级正确。
- [ ] 区域词条池、等级权重和变形池按最终快照生效。
- [ ] 技能显示名和主要技能参数可通过 reload 更新。
- [ ] 死亡播报和保护动物消息仍可正常触发。
- [ ] 生成炒鸡怪后卸载并重新加载区块，`/im stats` 的追踪数量恢复且技能仍可触发。
- [ ] 重启服务器后，等级、词条、禁用词条、一次性记录和变形目标池保持不变。
- [ ] 已触发过 `1up` 或巨型蛛网的实体，重载区块及重启后不会刷新一次性机会。
- [ ] 带 `mounted`、`armoured` 等词条的实体恢复时不会重复生成坐骑或装备。
- [ ] 人为破坏 `mczju:infernal_mob` 容器时只出现警告，实体不会被删除。
- [ ] 原版自然消失仍生效，关服时不会主动删除炒鸡怪。
- [ ] 将两份旧运行数据手工移动到 `data/` 后启动，统计和保底进度均能读取。
- [ ] 产生新击杀和保底进度后等待一分钟，两个数据文件均更新。
- [ ] 保存期间继续产生数据，下一次保存或关服保存后没有丢失新增进度。
- [ ] 临时令数据目录不可写，确认日志提示失败；恢复权限并等待下一周期后能够成功重试。
- [ ] 关闭服务器后检查最后一分钟内产生的数据已经落盘。
- [ ] 按第四阶段表格迁移全部掉落文件，启动日志不再引用旧文件路径。
- [ ] 各等级奖励池及 `drop-times` 次数与迁移前一致，特殊实体掉落仍正常。
- [ ] 同一保底规则配置两个轮换奖励时，每个月只显示并发放当前套奖励。
- [ ] 保底达到 `required-rolls` 时发奖；可重复规则直接归零，不保留超出阈值部分。
- [ ] `/im reload` 后新掉落立即生效，已有保底进度不清空。
- [ ] 破坏 `loot/settings.yml` 后 reload 失败，核心和掉落均继续使用旧快照。
- [ ] 实体死亡时 `lifesteal`、`spear` 等延迟任务被清理，且其他词条仍正常注销。
- [ ] `/im clear` 清除实体后没有残留技能任务或会话。
- [ ] 变形时旧实体的技能会话被清理，新实体可以正常继续触发技能。
- [ ] 变形触发后立即死亡或执行 `/im clear`，旧的延迟变形任务不会再次执行。
- [ ] `sulfur` 预警或喷发期间实体死亡、变形或被 `/im clear`，喷泉仍能安全完成并正常击飞玩家。
- [ ] 区块卸载/重载后常驻装配效果不被错误移除，恢复后的实体仍可正常运行。
